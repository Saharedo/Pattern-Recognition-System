Day 3: Reducing features with selection, PCA and LDA

This is the topic behind sample question 1e. You need to know how to pick the number of components, how to read the loadings table, and when PCA or LDA is the right tool.

1. Why reduce the number of features?

A dataset with n rows and p columns has dimension p (the number of features). High p causes four problems:

  • Cost: more memory, slower training.
  • Redundancy and overfitting: many features repeat each other or only add noise, so the model fits noise.
  • Curse of dimensionality: the space gets so large that your data points become sparse. You need far more rows to cover it.
  • Distances stop working. In very high dimensions the nearest and farthest points are almost the same distance away, so KNN and clustering lose their power.
  • Visualisation: you cannot plot beyond 3 dimensions.

Fewer features gives better performance (less noise), simpler and more explainable models, easy visualisation, and lower time and memory cost.

Two ways to reduce dimensions

Feature selectionKeep a subset of the original columns and drop the rest. Result stays easy to explain.
Feature extractionBuild new columns by combining the old ones (PCA, LDA). Result is harder to explain.

Wrapper methods in more detail

ForwardStart with no features. Add the one that improves the cross-validated score most. Repeat until you reach the target number.
BackwardStart with all features. Remove the weakest each round. Faster when you keep most of them (keep 7 of 10: forward needs 7 rounds, backward only 3).
RFETrain, rank features by coefficient or importance, drop the least important, retrain, repeat. Cheaper than plain backward because it uses the model's own ranking.

Lasso vs Ridge: both add a penalty on coefficient size. Lasso (L1) penalises the absolute value and shrinks some coefficients to exactly zero, which removes those features (selection). Ridge (L2) penalises the square, shrinks coefficients but keeps all of them.

Exam angle"Many features, which approach?" Name the family, say why: filter first because it is cheap and removes redundant features (correlated pairs, constant columns), then embedded or wrapper if accuracy matters, and always evaluate on held-out data. If explainability matters, use selection rather than PCA, because selected features keep their meaning.

3. Principal Component Analysis (PCA)

One linePCA builds new, uncorrelated features (components) that are weighted mixes of the old ones, ordered so the first keeps the most variance, the second the most of what is left, and so on.

Key properties (write these in the exam)

  • Linear combinations: PC1 = 0.314·Income + 0.237·Education + 0.484·Age + ... (the weights are the loadings or eigenvector coefficients).
  • Uncorrelated and orthogonal: no overlap between components, so no multicollinearity.
  • Ordered: PC1 explains the most variance, PC2 the next, etc.
  • Unsupervised: ignores class labels.
  • Eigenvalue = the variance a component explains. Eigenvector = its weights.

The workflow from the notes

  1. Understand the data: summary statistics, correlation matrix (are features related?).
  2. Check suitability: KMO and Bartlett's test (below).
  3. Standardise the features (PCA is about variance, so scale matters) and run PCA.
  4. Decide how many components to keep (Section 4).
  5. Interpret each kept component from its loadings and name it.
  6. Use the component scores as new features in a model, or in a score plot to see clusters and outliers.

4. How many components should you keep?

Three rules, usually used together. Always say which rule you used.

RuleHow
Kaiser ruleKeep components with eigenvalue greater than 1 (they beat a single original standardised feature, which carries 1 unit of variance).
Cumulative varianceKeep enough to reach a target such as 80% or 90% of total variance.
Scree plotPlot eigenvalues in decreasing order. Keep the components before the elbow, where a steep drop turns into a flat plateau.
CommunalitiesCheck each original variable keeps a communality above 0.5, so no feature is poorly represented by the kept components.

Exam angle (Q1e(i))Pick a number, name the rule, show the figure that supports it, and acknowledge a competing rule. A good answer: "About 8 (80.6% cumulative variance); Kaiser would allow 9 and the scree plot is gradual, so there is no sharp cut. The postulate of only a handful of factors is only partly true."
No-calculator trick: which components pass Kaiser?

Eigenvalue 1 corresponds to 100 / p percent of the variance. With p = 18 that is 5.56%. Any component explaining more than 5.56% passes (6.2% passes, 5.4% fails). No multiplication needed.

Interpreting the components (Q1e(ii))

A component is named by the features with large loadings (near +1 or −1). Reading the sample table:

Can the factors be used as predictors in a regression? Yes, with caveats:

  • Good: components are uncorrelated, so no multicollinearity, and there are fewer variables, which reduces overfitting.
  • Caution 1: a component can mix several ideas, and you lose the meaning of individual features, so it is harder to explain to the business.
  • Caution 2, leakage: in the sample table the target Revenue is itself included in the PCA, and PC4 loads on it. Using such components to predict Revenue leaks the answer. Run the PCA on the input features only.
  • Caution 3: PCA ignores the target, so the top variance components are not guaranteed to be the most predictive. Check by modelling.
  • Caution 4: fit PCA (and the scaling) on training data only, then apply to the test data.

5. Information loss and component scores

Keeping fewer components loses information. You can see how much by reconstructing the data from the kept components (pca.inverse_transform). In the notes' example one PC reconstructs 77% of the variation, two give 95.4%, and three give 99.97%. In image compression, 60 components may retain 95% of the picture.

Component scores are the values of the new features for each row (mean 0, standard deviation 1). A score of +2 on "Financial Stability" means two standard deviations above average. A score plot (PC1 vs PC2) shows clusters, separation between groups, and outliers. A loading plot shows which original variables push each component.

6. Linear Discriminant Analysis (LDA)

LDA also builds new axes but uses the class labels: it looks for directions that push class averages far apart while keeping each class tight.

7. Practice questions (exam style)

Question A: choose components

A PCA on 5 standardised features gives eigenvalues 2.5, 1.2, 0.8, 0.3 and 0.2. (a) Calculate the % of variance each component explains. (b) How many components do the Kaiser rule and a 90% rule keep? (c) A manager says "PC1 mostly loads on weight and height, so we can call it body size". Is that a valid way to interpret it? (4 marks)

Show the worked answer

(a) Total variance = 5 (number of standardised features, and 2.5 + 1.2 + 0.8 + 0.3 + 0.2 = 5.0). So the percentages are 2.5/5 = 50%, 1.2/5 = 24%, 0.8/5 = 16%, 0.3/5 = 6%, 0.2/5 = 4%.

(b) Kaiser keeps eigenvalues above 1: PC1 and PC2, so 2 components (74% of variance). A 90% rule needs 50 + 24 + 16 = 90%, so 3 components.

(c) Yes. A component is named from its features with large loadings, so if weight and height both load strongly with the same sign, "body size" is a sensible name. Back it up with the loading values and check the sign, and note the name is a human judgement.

Question B: PCA or LDA?

A hospital has 40 lab measurements per patient and a label (healthy, mild, severe). (a) Which of PCA and LDA suits preparing features for a classifier, and how many new features can it give? (b) Name one risk if you run the dimension reduction on all the data before splitting into train and test. (3 marks)

Show the worked answer

(a) LDA, because it uses the class labels to find directions that separate the classes. With 3 classes it gives at most 3 − 1 = 2 new features.

(b) Data leakage. The test patients influence the learned axes (and scaling), so the test score is optimistic. Fit on the training data only, then apply the same transformation to the test data.

Quick recall questions
  1. Filter, wrapper, embedded: which is fastest and which tends to be most accurate?
  2. Which regularisation can set coefficients exactly to zero?
  3. What does a significant Bartlett's test (p < 0.05) tell you?
  4. Eigenvalue of a component is 0.8 on standardised data. Does it pass Kaiser?
  5. How many discriminant axes can LDA give with 4 classes?

Answers: (1) Filter is fastest, wrapper tends to be most accurate. (2) Lasso (L1). (3) The variables are correlated enough that PCA can compress them. (4) No, it is below 1. (5) 3.
