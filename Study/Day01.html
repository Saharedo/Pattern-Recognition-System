Day 1: What pattern recognition is, and the toolkit you will reuse all week

Read this top to bottom. Every section ends with the exam angle, so you can see how the idea shows up in the sample paper. Open the "check yourself" boxes only after you have tried to answer.

1. What is pattern recognition?

A pattern is a regularity in data: the stripes of a shirt, the shape of a handwritten 7, the rhythm of a vibration signal. Pattern recognition means getting a computer to find such regularities and act on them, for example "this image is a kettle" or "this session will end in a purchase".

One line to rememberPattern recognition is the problem. Machine learning is the solution toolbox.

Every pattern is described as a list of numbers called a feature vector, written x = (x1, x2, ..., xd). For the bookstore case in the sample exam, one visitor session is one vector: pages visited, time on site, bounce rate, and so on. The thing you want to predict is the label y (bought or did not buy).

Three ways a machine can learn

Exam angleQuestions often start "which type of learning, and why?". Give the type, then tie it to the data: labels exist (supervised), no labels (unsupervised), or only reward feedback (reinforcement).

2. The pattern recognition pipeline

Any real system is a chain of stages. When an exam asks you to "describe how the model can be built", walk down this chain.

SenseCollect raw data: camera, sensor, web logs.
→
Pre-processRemove noise, fix missing values, scale.
→
FeaturesTurn raw data into useful numbers.
→
ModelClassify or cluster. Train, then test.
→
Post-processCheck confidence, apply business rules.

Deep learning shortcuts the middle: the network learns the features itself from raw data ("end to end"). Classical methods need a human to design the features.

3. Preparing the data

3.1 Scaling features

Many models measure distances or take steps proportional to feature size. If "Product related duration" ranges up to 63,973 and "Bounce rate" only up to 0.2, the big number swamps the small one. Scaling puts them on a comparable footing.

Min-max: x' = (x - min) / (max - min) result in [0, 1] Z-score: x' = (x - mean) / std result has mean 0, std 1
TrapCompute min, max, mean and std from the training set only, then reuse those same numbers on the test set and on new data. Using test data to compute them leaks information.

3.2 Splitting the data

Cross-validation repeats this: cut the data into k folds, train on k-1, test on the remaining fold, rotate, then average the k scores. It is useful when data is scarce.

3.3 Overfitting: the most important idea of the week

Generalisation is how well a model works on data it has not seen. To improve it: get more training data, use a simpler model, or reduce the number of features.

3.4 Too many features

The curse of dimensionality: with more features, you need far more data to cover the space, models get slower, and they overfit more easily. Two cures: feature selection (drop useless features) and dimensionality reduction such as PCA (unsupervised) or LDA (uses class labels). PCA gets its own day.

LDA vs PCA

LDA (Linear Discriminant Analysis) combines features into a few new ones chosen to separate the classes. PCA combines them to keep the most overall variance and never looks at labels.

3.5 Imbalanced data

The sample bookstore data is 84.5% "no purchase" and 15.5% "purchase". A lazy model that always says "no purchase" scores 84.5% accuracy and finds zero buyers. Fixes from the notes:

  • Oversample the rare class: random oversampling, or SMOTE (invent new rare-class points between existing neighbours).
  • Custom loss function: make a missed buyer cost more than a false alarm.
  • For images, augment: flip, rotate, scale, crop. For audio: add noise, shift pitch. Generative models (GAN, VAE, diffusion) can also create synthetic samples.
  • Judge the model by recall, precision, F1 or AUC, not accuracy.
Exam angleQ1a asks for "one problem with the current model and how to improve it". Class imbalance is the answer the data is practically shouting. Q2c is the extreme case: 3,000 normal and 2 abnormal samples.
Check yourself: why is 84.5% accuracy meaningless here?

Because a model that predicts "no purchase" for every visitor already gets 84.5%. Accuracy hides the failure on the minority class, which is the class the business cares about.

4. Measuring a classifier

4.1 The confusion matrix

Pick one class as "positive" (the one you are hunting for, here "will purchase"). Every prediction lands in one of four boxes.

Accuracy = (TP + TN) / all Recall = TP / (TP + FN) "of the real buyers, how many did I catch?" (= sensitivity) Precision = TP / (TP + FP) "of the ones I flagged, how many were real?" Specificity = TN / (TN + FP) "of the real non-buyers, how many did I leave alone?" F1 = 2 x Precision x Recall / (Precision + Recall)
Memory trickRecall and sensitivity look along the top row (all actual positives). Precision looks down the left column (all predicted positives). The denominator always tells you what the question is "out of".

Trap in the sample paperThe "Actual True" row totals 3,150 of 3,699 test rows (85%). But only 15.5% of sessions were purchases, so the row labelled True looks like the majority "no purchase" class. The table labels may be swapped. In the exam, say which class you treat as positive and why. The business goal decides: if wasted coupons are cheap and a lost sale is expensive, favour recall; if coupons are costly, favour precision.

4.3 ROC curve and AUC

Most classifiers output a score, and you choose a cut-off. Move the cut-off and the true positive rate and false positive rate both change. The ROC curve plots that trade-off. AUC is the area under it: 100% is perfect, 50% is a coin flip. Higher AUC means a better model, regardless of the cut-off chosen.

4.4 Hyperparameters

Hyperparameters are settings you choose before training, not numbers the model learns: k in KNN, C, kernel and gamma in an SVM, learning rate, dropout rate and batch size in a neural network. Find them by grid search (try every combination), random search, or Bayesian optimisation, scoring each on validation data.

5. Four supervised models

5.1 Linear regression (predict a number)

Model: y = a·x + b·z + ... + c. R² says how much of the variation in y the line explains: R² = SSreg / SStotal, between 0 and 1.

5.2 Logistic regression (predict a probability, then a class)

Despite the name, this is for classification. A straight line can go below 0 or above 1, which is useless for a probability. Logistic regression bends it into an S shape that stays between 0 and 1.

ln( P / (1 - P) ) = a + b1·x1 + b2·x2 + ... P/(1-P) = odds ln(P/(1-P)) = log-odds (logit)

The right side is a plain linear model. The left side is the log-odds. A positive coefficient means that feature raises the chance of the positive class. Multinomial logistic regression handles more than two classes.

5.3 K-nearest neighbours (KNN)

To classify a new point, find the k closest training points and take a majority vote. There is no real training step, which is why KNN is called a lazy learner.

  • Needs three things: stored training data, a distance measure (Euclidean or Manhattan), and k. Use an odd k to avoid ties.
  • Scale your features first, or the feature with the largest numbers decides everything.
  • Slow at prediction time on big data, because it compares against every stored point.

5.4 Naive Bayes (the one you may need to calculate by hand)

This is the model behind sample Q2d, so learn the recipe well. It uses Bayes' theorem to answer: "given what I observed, which class is most probable?"

P(class | evidence) = P(evidence | class) x P(class) / P(evidence) posterior likelihood prior same for all classes → ignore it

"Naive" means it assumes the features are independent given the class, so the likelihood becomes a simple product:

P(x1, x2, x3 | class) = P(x1 | class) x P(x2 | class) x P(x3 | class)

The recipe, with a fruit example from the notes

1,000 fruits: 500 banana, 300 orange, 200 other. A new fruit is Long, Sweet and Yellow. Which is it?

  1. Priors: P(class) = count of class / total rows.
  2. Likelihoods: for each observed feature value, P(value | class) = (rows of that class with that value) / (rows of that class).
  3. Score each class = prior x all likelihoods.
  4. (Optional) Normalise: divide each score by the sum of scores to get true probabilities that add to 1.
  5. Choose the class with the highest score.
Zero probability problemOrange scored exactly 0 because no orange was Long. One zero wipes out the whole product. Laplace correction: add 1 to every count (and add the number of possible values to the denominator), so nothing is ever exactly zero. Mention it whenever a count in your table is 0.

Strengths: fast, works with little data, good for categorical features. Weakness: real features are rarely independent.

Check yourself: why can we ignore P(evidence)?

It is the same number for every class, so it cannot change which class has the largest score. It only matters if you want the actual probabilities to add to 1.

6. Practice question (exam style)

Try this on paper before opening the answer. It uses the same method as sample Q2d, with a different table.

A pump monitoring system records temperature and noise level at the time of a fault. The cause is later found to be Worn bearing or Loose mounting.

No.TemperatureNoiseCause
1HotLoudWorn
2HotQuietWorn
3CoolLoudLoose
4HotLoudWorn
5CoolQuietLoose
6CoolLoudWorn
7HotQuietLoose
8CoolQuietLoose

(a) Use a Naive Bayes classifier to decide the cause when the pump is Hot and Loud. Show your working. (b) State the independence assumption you relied on and whether it is realistic here. (4 marks)

Show the worked answer

Priors: Worn = 4/8 = 0.5 (rows 1, 2, 4, 6). Loose = 4/8 = 0.5 (rows 3, 5, 7, 8).

Likelihoods for Worn: P(Hot | Worn) = 3/4 (rows 1, 2, 4). P(Loud | Worn) = 3/4 (rows 1, 4, 6).

Likelihoods for Loose: P(Hot | Loose) = 1/4 (row 7). P(Loud | Loose) = 1/4 (row 3).

Scores: Worn = 0.5 x 0.75 x 0.75 = 0.28125. Loose = 0.5 x 0.25 x 0.25 = 0.03125.

Normalise: total = 0.3125, so P(Worn | Hot, Loud) = 0.90 and P(Loose | Hot, Loud) = 0.10.

Decision: Worn bearing.

(b) It assumes temperature and noise are independent once the cause is known. That is questionable: a worn bearing raises both heat and noise through the same friction, so the two readings are probably correlated even within one cause. The method may therefore be overconfident, but it usually still ranks the classes correctly. With only 8 records, no count is zero here, so Laplace correction was not needed, but it would be wise with more categories.

Quick recall questions
  1. Which learning type needs labels? Which needs only reward?
  2. Why must the scaling parameters come from the training set only?
  3. You raise k in KNN from 1 to 25. What happens to noise sensitivity and to the boundary?
  4. A model has 95% accuracy on training and 70% on test. What is the problem and name two fixes?
  5. Which metric answers "of the real buyers, how many did I find?"

Answers: (1) Supervised needs labels, reinforcement needs only reward feedback. (2) Otherwise test information leaks into training and the score is too optimistic. (3) Less sensitive to noise, but a smoother boundary that may blur classes. (4) Overfitting; use more data or a simpler model, or fewer features. (5) Recall.
