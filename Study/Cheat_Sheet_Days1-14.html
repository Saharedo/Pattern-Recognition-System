A. Answer routine and quick facts

  • Which learning type? Labels given = supervised. No labels = unsupervised (clustering, PCA). Only reward feedback = reinforcement.
  • Pipeline: Sense, Pre-process, Features, Model, Post-process. Deep learning learns the features itself from raw data.
  • "What is wrong and how to improve?" (1) quote the numbers, (2) name the problem, (3) fix it with a reason, (4) say which metric proves it improved.
  • No calculator: write the formula, substitute, then estimate. Compare sizes instead of computing. Keep fractions.
  • Fraction to decimal: 1/8 = .125 · 1/5 = .2 · 1/4 = .25 · 1/3 = .33 · 3/8 = .375 · 2/5 = .4 · 1/2 = .5 · 5/8 = .625 · 2/3 = .67 · 3/4 = .75 · 4/5 = .8 · 1/20 = .05 · 17/20 = .85
  • Recommending a model? Your reasons must match your recommendation (needs explaining to patients, regulators or marketing = decision tree; then state its cost).

B. Data preparation and overfitting

  • Min-max (x−min)/(max−min) gives 0 to 1. Z-score (x−mean)/std gives mean 0, std 1.
  • Scaling parameters come from the TRAINING set only. Reuse the same numbers on validation, test and new data. Using test data leaks information.
  • Scale for: KNN, SVM, neural nets, PCA, K-means, DBSCAN, Lasso. Not for: decision trees (a split only moves its threshold).
  • Split: training (about 70%) learns. Validation tunes. Test is used once at the end. Cross-validation (k folds, average the k scores) is done inside the training data.
  • Order of steps: split, fit scaler on train, fit PCA or LDA on scaled train, apply the same scaler and PCA to test.
  • Overfitting: train score high, validation or test score low. Fix: more data, simpler model, fewer features, regularise (L2, dropout), early stopping, prune the tree, lower C or gamma, cross-validate.
  • Curse of dimensionality: data becomes sparse and near and far distances look alike, so KNN and clustering weaken. Cures: feature selection, PCA or LDA.
  • Imbalance (always saying "no" scores 84.5% or 98%): accuracy hides it. Fix with class weights or a custom loss, SMOTE or oversampling the rare class, undersampling the common class, augmentation. Judge by recall, precision, F1, AUC.
  • Hyperparameters are set before training and tuned on validation data (grid, random, Bayesian search): k, C, gamma, kernel, learning rate, dropout, batch size, max_depth.

Recall = TP/(TP+FN): of the real positives, how many caught (top row). Precision = TP/(TP+FP): of those flagged, how many real (left column). Specificity = TN/(TN+FP). Accuracy = (TP+TN)/all. F1 = 2PR/(P+R).

  • Always write TP, FN, FP, TN first. Example: TP 15, FN 5 gives recall 15/20 = 3/4 = 0.75.
  • Which to favour: a miss is costly (disease, fraud, lost sale) = recall. A false alarm is costly (coupons, investigations) = precision.
  • Compare two models without dividing: same actual positives, so fewer FN = higher recall. Write a rate as 1 − small fraction. Then state the business trade-off in words.
  • A model that predicts all "negative" has high accuracy and recall 0.
  • ROC/AUC: plots the true positive rate against the false positive rate across cut-offs. AUC 1 = perfect, 0.5 = guessing, independent of the cut-off.
  • Check which class the table treats as positive. State your choice.

D. Regression, KNN, Naive Bayes

  • Linear regression: least squares. R² = SSreg/SStotal = share of the variation in y explained (0 to 1). A coefficient is the change in y for +1 in that x, others held fixed.
  • Logistic regression (classification): ln(P/(1−P)) = a + b1x1 + … (log-odds). Positive coefficient raises the chance of the positive class. Output is a probability, cut-off 0.5 is movable.
  • KNN: lazy learner, majority vote of the k nearest points. Small k follows noise, large k blurs the boundary. Use odd k. Scale first. Slow at prediction time.
  • Naive Bayes: score(C) = P(C) × P(x1|C) × P(x2|C) × … . P(value|C) = rows in class C with that value ÷ rows in class C. Pick the largest. Probability = own score ÷ sum of scores.
  • Count is 0? One zero wipes out the product. Laplace: add 1 to each count and add the number of possible values to the denominator.
  • By hand: cancel the shared prior, compare ratios (9/16 vs 1/16 = 9:1 = 90% / 10%).
  • Independence assumption = features independent given the class. Often unrealistic (a worn bearing raises both heat and noise). Probabilities become overconfident but the ranking is often still right.
  • Numeric features: model each class with a Gaussian, p(x|class) = 1/√(2πσ²) · exp(−(x−μ)²/(2σ²)), with μ and σ² estimated per class from training data.
  • Worked (play tennis), x = Sunny, Cool, High, Strong: Yes = 2/9·3/9·3/9·3/9·9/14 ≈ .0053. No = 3/5·1/5·4/5·3/5·5/14 ≈ .0206. No is about 4× bigger, so P(No|x) = .0206/(.0053+.0206) ≈ .80. Estimate fast: .0082×.64 and .0576×.36.
  • Sensor table (Q2d): count the prior of each cause (records of that cause ÷ all records), count each likelihood inside the cause, multiply, compare, show every fraction. Pump example: Fault 3/8·2/3·1/3 = 1/12, Normal 5/8·1/5·4/5 = 1/10, so Normal (ratio 10:12, P(Normal) = 6/11). Zero count: Laplace, (0+1)/(3+2) = 0.2.

E. Decision trees

Node = test on one feature, branch = outcome, leaf = class. Readable rules, no scaling needed, boundaries are steps.

Entropy E = −Σ p·log₂p. Pure = 0, 50/50 = 1. Gini = 1 − Σp² (pure 0, 50/50 = 0.5).

Proportion = count in the class ÷ TOTAL in that node. "1 default, 5 repaid" is 1/6 and 5/6, not 1/5.

Gain = E(parent) − Σ (child size ÷ parent size) × E(child). The weights add to 1. Gain can never exceed E(parent). GainRatio = Gain / IntrinsicInfo (penalises many-valued features such as an ID code, which has top gain but memorises).

Entropy is symmetric: E(p) = E(1−p), so 3/4 = 1/4 and 2/3 = 1/3. Farther from 50/50 = purer = lower entropy.

  • Best split = lowest weighted child entropy. Check how far each child is from 50/50. A perfectly pure child contributes 0, so it often wins even if small. Mirror-image splits tie. If each child has the same mix as the parent, gain = 0.
  • Estimate: compute each child's E from the table, multiply by its weight, add, subtract from E(parent). Example: parent 5/5 (E 1), children (4/5, 1/5) twice gives 1 − .72 = .28. Children (pure 4 of 10) and (1/6 for 6 of 10) gives 1 − .6×.65 = .61, so the second wins.
  • Logs left as expressions: E(1/6) = log₂6 − (5/6)log₂5. Useful: log₂3 ≈ 1.58, log₂5 ≈ 2.32, log₂7 ≈ 2.81, log₂(3/4) = log₂3 − 2. Bounds: 3² = 9 > 8 so log₂3 > 1.5; 5² = 25 < 32 so log₂5 < 2.5.
  • Continuous feature: sort the values; candidate cuts are the midpoints of adjacent distinct values (20, 30, 45, 60 gives 25, 37.5, 52.5). Pick the cut with the highest gain. A cut that gives the same partition as another is redundant.
  • Overfit tree (100% train, much lower test): pre-prune (max_depth, min_samples_leaf) or grow fully then post-prune on validation data.
  • Reading a tree: follow the path, quote the leaf's share and purity, give the business meaning, name one flaw (imbalance, depth, overfitting) and the metric to judge the fix.

F. Neural networks

  • Neuron: net = Σ w·x + b, out = f(net). The activation is applied to the net input, not to the raw inputs.
  • Activations: hard-limit (0 if net ≤ 0, else 1) · sigmoid 0 to 1 (net 0 gives .5, negative net gives below .5) · tanh −1 to 1 (same sign as net) · ReLU max(0, net) (cheap, no vanishing gradient, sparse) · softmax (outputs sum to 1).
  • Linear activations collapse: h = 4x then y = 0.5h means y = 2x, one neuron. Non-linearity lets extra layers draw curved boundaries.
  • Output and loss: 2 classes = sigmoid + binary cross-entropy. Many classes, one label = softmax + categorical cross-entropy. Number = linear + MSE. Several labels at once = sigmoid + binary cross-entropy. Hidden layers: ReLU.
  • Perceptron rule: Δwi = η(T−O)xi, with x0 = 1 for the bias. Correct output means no change. One perceptron draws one line, so XOR (opposite diagonals) fails. Two hidden nodes draw two lines and the output combines them.
  • Backprop (sigmoid): δout = O(1−O)(T−O), Δw = η·δ·Oin, hidden δj = Oj(1−Oj)Σδk·wkj. Sign check: target above output gives δ > 0, weight up, output up.
  • Loop: small random init, forward pass, loss, backward pass, update, repeat. Batch, stochastic or mini-batch (usual).
  • Learning rate: too big overshoots, oscillates or diverges. Too small is slow or stuck. Bigger is not always faster. Momentum: adds a fraction of the previous update, smooths the path and carries over shallow dips.
  • Never start with all-zero or identical weights: neurons stay identical (symmetry). Use small random values (Xavier or He).
  • Overtraining: train loss falls, validation loss rises. Stop at the validation minimum and keep those weights. Also: dropout (training only, off at test), L2, fewer nodes or layers, more or augmented data.
  • Scaling inputs: a feature in the thousands swamps one in the ones. Parameters from the training set only.
  • Why deep learning took off (2012 AlexNet): ReLU, dropout, GPUs, ImageNet (1.2M images). Not backprop (1986). Earlier failures: tiny data, slow computers, bad init, sigmoid vanishing gradients.
  • History: 1943 McCulloch-Pitts (0/1, fixed weights, no learning). 1958 perceptron (learns weights). 1969 XOR problem, first winter. 1986 backpropagation. Late 80s deep nets fail, SVMs and forests take over. 2012 AlexNet (15.3% top-5 error vs 26.2%).
  • Layer capability: first hidden layer draws lines (hyperplanes), the next combines them into convex regions, a further layer builds concave regions. Start with about √(inputs × outputs) hidden nodes; too many overfit.
  • Loss and gradient descent: MSE for numbers, cross-entropy for classes. Batch (all rows), stochastic (one row, noisy), mini-batch (n rows, the usual). Hand example: O = 0.508, T = 0, η = 0.3: δ = 0.508·0.492·(−0.508) = −0.127, Δw = 0.3·(−0.127)·1 = −0.038 (weight pushed down).
  • Classical vs deep learning: classical = works on small or medium data, hand-made features (HOG, SIFT), minutes to hours, some models explainable. Deep = needs big data and a GPU, learns features, hours to weeks, hard to explain.

RBF network

  • Three layers: input, hidden (kernel) nodes, linear output. Gaussian kernel Oi = exp(−(x−ci)ᵀ(x−ci) / (2σi²)). Output Oj = Σ Wji·Oi.
  • Two-stage training: (1) centres and widths from unsupervised clustering (hard C-means): cj = mean of cluster j, σj² = (1/mj) Σ (x−cj)ᵀ(x−cj) = average squared distance to the centre. Few samples: use each sample as a centre. (2) Output weights by the supervised delta rule Wji(t+1) = Wji(t) + η·δj·Oi, δj = Tj − Oj, repeated until convergence.
  • Needs few labels (stage 1 is unlabelled) and converges in a few epochs. XOR example: 4 hidden units centred on the 4 patterns, output weights start at 0.5, η = 0.5: for P1 only C1 fires, Out = 0.5, Wo1 = 0.5 + 0.5·(0−0.5)·1 = 0.25; for P2 Wo2 = 0.5 + 0.5·(1−0.5)·1 = 0.75.

GRNN (general regression neural network)

  • Memory-based, one-pass, self-growing. Layers: input, pattern (one node per training pattern or cluster centre, weights = the stored exemplar or centroid), summation (two kinds, A and B), output (a division).
  • Pattern node oi = exp(−Di² / 2σ²), Di² = (x−wi)ᵀ(x−wi). Output ẑ = Σ Ai·exp(−Di²/2σ²) / Σ Bi·exp(−Di²/2σ²), a weighted average of the stored targets; the nearest patterns count most.
  • Learning: each time a training target zj is seen for pattern i: Ai ← Ai + zj (running sum of targets) and Bi ← Bi + 1 (count), starting from 0.
  • σ (smoothing constant) is found experimentally. Small σ: narrow peaked surface that fits the sample points (overfits). Large σ: flatter, smoother surface. Aim for a trade-off. Aircraft example: any σ from 0.1 to 5.0 was satisfactory.
  • Pros: converges to the true regression surface as samples grow, works with sparse data and in real time, fast single-pass training, can start after one sample. Cons: grows large (one node per pattern unless clustering is used), heavy computation. Used for forecasting and control.
  • Aircraft comparison: the MLP needed 50 nodes per hidden layer and over 50 epochs, the RBF used 18 basis nodes and a few epochs, the GRNN used one pass (1,600 or 200 nodes) and had the lowest errors.

SOM (Kohonen map)

  • Unsupervised competitive learning, winner takes all. Output nodes sit on a 1D row or 2D lattice. The input is fully connected to every node.
  • Algorithm: initialise weights randomly in (0,1); present x; the winner r is the node with the smallest ‖x − wr‖; update the winner and its neighbours wr' ← wr' + α·hrr'·(x − wr'); repeat until the weights stabilise; shrink the neighbourhood and α over time. h is largest at the winner and falls to 0 with distance (square, hexagonal or Gaussian neighbourhood), so nearer nodes move more.
  • Pros: alternative to K-means with no preset k, compression, visualisation, can classify if labelled. Uses: travelling salesman, robot-arm control (data fusion), signature authentication (SOM + MLP hybrid).

G. CNN

  • Output = floor((W − F + 2P)/S) + 1. "Same" padding: P = (F−1)/2 keeps size at stride 1. Pool 2×2 stride 2 gives floor(W/2) (11 gives 5).
  • Conv params (Fr·Fc·Cin + 1)·Cout · Dense in·out + out · Pool, Flatten, Dropout = 0.
  • Examples: 128, 7×7, stride 2 gives 61. 64×64×3 with 5×5 and 10 filters gives 60×60×10 and (75+1)·10 = 760 params. Conv 7×7, 3 channels, 18 filters = 2,664.
  • Convolution by hand: multiply the kernel with each window element by element, add up, slide. Kernel [1 0; 0 1] just adds the main diagonal. Early layers find edges, deeper layers shapes and objects.
  • Max pool: halves height and width, keeps the strongest value, no parameters, tolerates small shifts. Filters are learned by training; you only choose size and number.
  • Why CNN for images: local connections plus shared weights (far fewer parameters) and tolerance to position.
  • Critique a CNN (Q2a): table of shapes and params. The first Dense after Flatten dominates (9,408 × 256 = 2.4M of 2.58M, 93%). With about 5,000 images and 918 classes (about 5 per class) this overfits.
  • Fixes: Global Average Pooling (9,408 inputs down to 48), dropout, batch norm, augmentation, class weights, transfer learning.
  • Several attributes (brand 18, type 17, value 3): shared backbone, one softmax head per attribute, summed cross-entropy. About 280, 290, 1,670 images per class instead of 5. New total 69,302 params (GAP + three heads), not 2,465,462 (heads only).
  • Flatten: length = H × W × C of the last feature map, 0 parameters. 4×4×6 gives 96. 4×4×64 gives 1,024. 14×14×48 gives 9,408. First Dense after Flatten = (H·W·C)·units + units (96·36 + 36 = 3,492).
  • Keras pattern: Conv2D(32,(3,3),padding='same',activation='relu'), MaxPooling2D((2,2)), repeat, Flatten(), Dense(256,'relu'), Dense(10,'softmax'), compile(loss='categorical_crossentropy', optimizer=…, metrics=['accuracy']). Input shape (samples, rows, columns, channels), scaled to 0 to 1. A batch of 32 has shape (32,16,16,1): forward pass, loss, backprop (automatic differentiation), optimiser updates the weights.
  • Small net, 16×16×1: Conv 3×3, 3 filters, same (30 params) → pool 8×8×3 → Conv 3×3, 6 filters (28·6 = 168) → pool 4×4×6 → Flatten 96 → Dense 36 (3,492) → Dense 5 (185). Total 3,875.
  • Digit net, 28×28×1, 5×5, no padding: Conv 20 gives 24×24×20 (520 params), pool 12×12×20, Conv 40 gives 8×8×40 (20,040), pool 4×4×40, Flatten 640, Dense 128 (82,048), Dense 10 (1,290). Total 103,898.

H. Training deep networks and Keras (Days 8 and 9)

  • Depth over width: one hidden layer can approximate any function in theory (universal approximation) but gives no way to find the weights. AlexNet test (8 layers, 60M params, top-5 accuracy 81.9%): remove dense 7 (60M to 44M) −1.1 points; dense 6 and 7 (to 10M) −5.7; conv 3 and 4 (60M to 59M) −3.0; conv 3, 4 and dense 6, 7 (9M left) −33.5. More parameters is not better; convolutional depth matters more than a giant dense layer.
  • Keras Sequential: one input, one output, straight stack. Functional API: multiple inputs or outputs, branches, shared layers, skip connections (ResNet). Two inputs (video + question): separate extractors then concatenate. Two outputs (enhanced image + segmentation map): shared encoder, one head each. Shared layers: same weights on two inputs (re-identification).
  • Output and loss: regression linear + MSE. Binary sigmoid + binary cross-entropy. Multi-class softmax + categorical cross-entropy (one-hot labels). model.summary(): check output shapes and Param #; Conv2D 3×3, 32 filters on 3 channels = (27+1)·32 = 896.
  • Vanishing gradient: backprop multiplies many activation derivatives. Sigmoid derivative is at most 0.25 (tanh also saturates), so the product shrinks and early layers barely learn. ReLU derivative is exactly 1 for active units. Fix: ReLU, good initialisation, batch norm, skip connections.
  • Initialisation: never all zeros (identical units). Too small: signal dies, dead neurons. Too large: saturation. Xavier/Glorot for sigmoid and tanh (variance about 1/n, Keras default). He for ReLU (normal, mean 0, variance 2/n, n = fan-in; he_normal).
  • L2 (weight decay): loss + λΣw². Update w ← (1 − αη)·w − η·∂J/∂w. Keras l2(0.001); larger value = stronger penalty and a simpler model.
  • Dropout: zero a fraction p (0.2 to 0.5) of outputs during training only, a different set each step; like averaging many thin networks. Off at test time.
  • Batch normalisation: per mini-batch v̂ = (v − μB) / √(σB² + ε), then u = γ·v̂ + β (γ and β learned). Stabilises later layers, speeds training, slightly regularises. Order: Conv → BN → ReLU. Params: 4 per channel (γ and β trainable; running mean and variance not), so 32 channels = 128 params, 64 trainable.
  • Data augmentation (flips, rotations, shifts, crops, brightness): new variants each epoch, good for small or imbalanced sets. Early stopping: stop when validation loss stops improving and keep the best checkpoint.
  • Optimiser: SGD, or Adam and RMSprop (adapt the step per weight using running averages of gradient and squared gradient); Adam with learning rate 0.001 is a common start. Lower the rate with a schedule. Large batch: faster, needs GPU memory, may generalise worse. Small batch: noisier, mild regularising effect.
  • Degradation is not overfitting: a much deeper plain network can have higher training error than a shallow one. Overfitting = low training error, high test error. Example: 40-layer sigmoid CNN 55% train and 54% validation vs a 10-layer one at 75% train: vanishing gradients and degradation. Fix: ReLU, He init, batch norm, residual connections, Adam or a tuned rate.
  • ResNet: a block learns the residual F(x) and outputs H(x) = F(x) + x (skip connection). If identity is best, F(x) goes to 0, which is easy, so extra blocks cannot make it worse. The skip also gives gradients a short path back. A "down" block uses stride 2 on its first conv and a 1×1 conv on the shortcut to match shapes.

I. Sequences: RNN, LSTM, transformers (Days 8 and 9)

  • RNN: reads one element at a time and carries a hidden state forward, so input length can vary and earlier steps matter. CNN = spatial data, RNN = sequential or temporal data.
  • Make windows: cut the series into fixed-length windows (time steps), moving by a chosen distance. 0,1,1,3,2,2,4,5,4,7,8,8,9 with length 4 and distance 3 gives [0,1,1,3] [3,2,2,4] [4,5,4,7] [7,8,8,9]. 2,4,…,14 with length 3 and distance 2 gives [2,4,6] [6,8,10] [10,12,14]. Each sample has shape (time steps, features); pair it with a target (next value or a window label). Split by time order (or by session), never random rows.
  • Parameters: SimpleRNN H(D+H) + H (D inputs per step, H hidden). D = 64, H = 32: 32·96 + 32 = 3,104. Dense(1) on 32 = 33. LSTM is 4× that: 4[H(D+H) + H]. D = 64, H = 32 gives 12,416. D = 2, H = 10 gives 4·(10·12 + 10) = 520.
  • Stacked LSTM: return_sequences=True on every LSTM except the last. (3 steps, 5 features) → LSTM 7: 4·(7·12+7) = 364, output (3,7) → LSTM 9: 4·(9·16+9) = 612, output (9) → Dense 1: 10.
  • Why LSTM: a plain RNN over 500 steps is a very deep net, so gradients vanish and distant context is forgotten. The LSTM has a cell state (conveyor belt) with gates: forget (how much old memory to keep), input (how much new to write), output (how much to expose). GRU is a lighter variant.
  • Output layer decides the task: regression Dense(1) linear + MSE. Binary Dense(1) sigmoid + binary cross-entropy. Multi-class Dense(k) softmax + categorical cross-entropy.
  • Q1d clickstream answer: LSTM or GRU, because the order of pages, time on each and the path matter. Each session is one sequence; each step has page category (one-hot or embedding), time spent, how the user arrived, next page; label = purchase or not (many-to-one). Pre-process: sort by time, pad or cut to a fixed length (masking) or window, scale numbers, handle imbalance (class weights, oversampling), split by session (and time). Combine with earlier models: feed the LSTM's purchase probability or final hidden state as an extra feature into the tabular model, or stack or average the predictions (hybrid). It adds browsing behaviour that aggregated page counts miss.
  • Transformer: self-attention replaces recurrence: every token looks at every other directly, long-range links are easy, training is parallel. Each token makes a query (what I look for), key (what I offer) and value (the information). Attention = softmax(QKᵀ/√dk)·V. Multi-head attention captures different relationships. Positional encoding adds order. Encoder block: self-attention, Add & Norm, feed-forward, Add & Norm. Decoder: masked self-attention (cannot see the future), cross-attention to the encoder, feed-forward. Encoder-only (BERT) = understanding, decoder-only (GPT) = generation, encoder-decoder = translation. Why attention over RNN: direct links between any positions, parallel training, long context.

J. Support vector machines

Score w·x + b. Dashed lines are the margin edges (±1). Ringed points are support vectors.
  • Class = sign of the score. |score| ≥ 1: beyond the margin. = 1: on the edge, a support vector. Between −1 and 1: inside the margin, still takes the sign's class (soft margin only). = 0: on the boundary.
  • Margin = 2/‖w‖. w = (3,4): ‖w‖ = 5, margin 0.4. w = (2,0): margin 1.
  • Minimise ½wᵀw (= ½‖w‖²) to make the margin as wide as possible, subject to yᵢ(w·xᵢ+b) ≥ 1. Without the constraint, w = 0 wins: every point scores the same and nothing is classified.
  • Support vectors alone define the boundary. Delete any other point and nothing changes. Hard margin: only the points exactly on the edges (at least 2, one per class). Adding far-away points changes nothing; points near or inside the margin can.
  • C small: wide margin, tolerant, more support vectors, smoother, risk of underfitting. C large: narrow margin, fewer support vectors, bends to fit noise or an outlier, risk of overfitting.
  • Kernel trick: a kernel gives dot products as if the data were in a higher dimension, without building the new coordinates. A ring becomes separable by a flat boundary. Linear, polynomial, RBF.
  • Gamma (RBF): large = tight blobs around points, 100% train but poor test (overfit). Small = smooth. Overfit RBF-SVM: lower C and gamma.
  • Multi-class: one-vs-rest = c SVMs, take the highest score. One-vs-one = c(c−1)/2 SVMs (5 classes = 10), majority vote.
  • Scale inputs (distance-based). No direct probabilities. Hard to interpret. Slow on very large data. Imbalance: use class weights.

Selection vs extraction

Selection keeps original columns (still explainable). Extraction (PCA, LDA) builds new ones (harder to explain).

  • Rounds: keep m of p features. Forward needs m rounds, backward needs p − m. (Keep 10 of 12: 10 vs 2. Keep 2: 2 vs 10.) Choose the cheaper.
  • Lasso (L1) sets some coefficients exactly to 0 (selection). Ridge (L2) shrinks but keeps all.

PCA

  • Unsupervised. New components are weighted mixes of the features: uncorrelated, orthogonal, ordered by variance explained. Eigenvalue = variance of a component, eigenvector = its weights (loadings).
  • Standardise first: PCA maximises variance and variance depends on units (grams would dominate cm). Standardised total variance = p, each feature 1.
  • eigenvalue = %var × p / 100. Kaiser: keep eigenvalue > 1, i.e. %var > 100/p (8 features: 12.5%). Other rules: cumulative 80 or 90% (reaching it counts), scree elbow, communality > 0.5 for each variable.
  • Rules can disagree (eigenvalues 2.4, 1.5, .9, .6, .3, .3: Kaiser keeps 2, 80% keeps 3, 90% keeps 4). Name the rule, quote the numbers, mention the other.
  • Suitable? KMO ≥ 0.5 (below = too little correlation). Bartlett p < 0.05 (rejects "variables unrelated"). KMO .35 and p .40: unsuitable. Do not force PCA; keep original features or add related variables. PCA needs correlation, so do not remove correlated features first.
  • Reading loadings: large |loading| (near ±1) defines the component. Same sign = move together, opposite sign = opposite. Near 0 = no role. Name it in business terms (Salary +, Bonus +, Rent − = "financial comfort").
  • Limits: linear, outlier-sensitive, continuous variables, enough rows (150+, about 5 per variable), components harder to explain. PCA ignores the target, so a top-variance component is not guaranteed to predict well, and a small one can be the useful one.
  • Using PCs in a model: uncorrelated and fewer inputs. Leave the target out of the PCA (leakage). Fit on training data only.

LDA

  • Supervised. Finds directions that push class means apart relative to the spread inside each class. Axes ≤ min(p, c−1) (30 features, 5 classes: 4. 4 features, 7 classes: 4).
  • PCA vs LDA: no labels, explore, compress = PCA. Labelled, prepare for classification = LDA. If classes overlap along the biggest-spread direction and differ along a small-spread one, PC1 puts them on top of each other (classifier near chance) while LDA finds the separating direction.
  • LDA assumes roughly Gaussian classes, fails if the classes differ in variance not mean, unstable with small samples. Fit on training data only.

L. Clustering and mixture models

  • Unsupervised. Minimise intra-cluster distance, maximise inter-cluster distance. Scale first.
  • Distances: Euclidean √Σ(diff)². To compare, compare the squared distances and skip the root. Manhattan Σ|diff|. Nominal: Hamming (match 0, mismatch 1, add up). Ordinal: map to ranks, then |difference|.

K-means

  • Choose k. Seeds, then assign each point to exactly one nearest centre, set each centre to the mean of its points, repeat until nothing changes. SSE = Σ (distance to own centre)².
  • Check each iteration: every point appears in exactly one cluster, and each centre is the average of its cluster (mean of 2, 4, 6 is 4).
  • Reaches a local minimum, so results depend on the seeds: restarts (keep the lowest SSE) or K-means++. Weak: must choose k, outliers drag centres, prefers round equal-size clusters, numeric only. Variants: K-medoids (robust), K-medians, K-modes, K-prototypes.

Hierarchical

  • Merge the two closest clusters repeatedly; the dendrogram records it. Merges cannot be undone. Cut with a horizontal line in the largest gap between merge heights; the number of branches crossed is the number of clusters.
  • Linkage: single = closest pair (chaining), complete = farthest pair (compact), average = mean of all pairs, Ward = smallest SSE increase. Pair distances 2, 6, 5, 8: single 2, complete 8, average 21/4 = 5.25.

DBSCAN

  • Settings ε and MinPts; no k. Core: at least MinPts points within ε. Border: inside a core's ε but not dense itself. Noise: neither, which makes the anomalies.
  • ε: plot each point's distance to its k-th neighbour (k = MinPts), sort, take the elbow. MinPts ≥ dimensions (2D: 4; above 2D: 2 × dimensions).
  • Choose: big data, round clusters = K-means. Any shape, outliers or fraud = DBSCAN. Small data or nested groups = hierarchical.

Is the clustering any good?

  • Silhouette s = (b − a)/max(a, b). a = average distance from the point to the others in its own cluster. b = average distance from the point to the points of the nearest other cluster. Example: point 4 in {2, 4}, other cluster {10, 12, 14}: a = 2, b = (6+8+10)/3 = 8, s = 6/8 = 0.75. Above 0.3 acceptable, near 0 on a border, negative probably misplaced.
  • Davies-Bouldin: lower is better. Calinski-Harabasz: higher is better. Elbow (WCSS): choose the k where the improvement flattens (500, 200, 120, 110, 105 gives k = 3). WCSS always falls and hits 0 at k = n, so never pick the minimum.
  • Stability: split-half, same clusters and profiles. Tiny clusters may be outliers.
  • Business lens: profile each cluster on its variables (means, box plots), give an intuitive name and an action. A good silhouette alone is not enough.
  • Fraud with no labels: DBSCAN, scale numeric features, encode categories. Judge by analysts reviewing a sample of the flagged cases (precision), stability and the k-distance plot; later recall when labels exist.
  • Gaussian mixture and EM: use when data forms several blobs and the group of each point is hidden. GMM = several Gaussians with weights. EM: (1) initialise parameters, (2) E-step: for each point, soft membership P(component|x) ∝ P(x|component)·P(component), (3) M-step: re-estimate each component's parameters and weight using those soft labels, repeat until stable. K-means is the hard-label cousin; GMM gives soft memberships and elliptical clusters. Points with very low probability under the mixture are anomalies.
  • Dice example: start P(6|Yellow) = .4, P(6|Blue) = .1, priors .5 each. For a roll of 6: Yellow .4·.5 = .2, Blue .1·.5 = .05, so P(Yellow|6) = .8, P(Blue|6) = .2. After all 18 rolls the M-step adds the soft counts (yellow 7.31 of 18) so P(Yellow) = .41, P(Blue) = .59, and P(1|Yellow) = 1.71/7.31 = .234.

M. Ensembles and hybrid models (Day 10)

  • Ensemble = committee (vote for classes, average for numbers). It beats its members if and only if they are accurate and diverse (Dietterich). Majority of 3 independent models with accuracy p: 3p²(1−p) + p³. p = .7: 3·.49·.3 + .343 = .784. p = .8: 3·.64·.2 + .512 = .896.
  • Bias and variance: error = bias² + variance + noise. High bias = underfit (shallow tree). High variance = overfit (deep unpruned tree). Averaging many flexible models cuts variance without raising bias (by less than 1/N because the models are correlated).

  • Boosting steps: equal weights, train, raise weights of wrong rows, train a new model on the reweighted data, repeat, combine with weights. Gradient boosting (XGBoost) fits each new model to the remaining error. Stacking: different model types, then a meta-model learns how to combine them. Bagging helps unstable models (deep trees, nets), not stable ones (linear, KNN). Under 50 models is usually enough.
  • OOB error: each tree leaves out about 37% of rows. Predict each row using only the trees that did not see it, vote, compare to the label. Gives an error estimate with no separate test set.
  • Variable importance: impurity-based (sum of Gini or entropy reduction over all splits and trees; biased towards variables with many levels) and permutation (shuffle one variable in the OOB data and measure the accuracy drop; works for any model).
  • Q1c answer: the single tree used only PageValue (root) and BounceRate. AdaBoost spreads importance (most 0.07 to 0.10, ProductRelated top at 0.10, Weekend 0.00). Reasons: a single tree is greedy and masks correlated features (ProductRelated and its duration, BounceRate and ExitRate); boosting reweights and sums over many trees so later trees use other variables; impurity importance favours many-level variables (Browser, OperatingSystems); flat scores mean many weak signals. Use: drop the lowest (Weekend, Region, Month, TrafficType), retrain SVM, NN or logistic on the top variables, compare by cross-validation, cross-check with permutation importance, keep business-critical variables.
  • Pick: noisy or mislabelled data, robust fraud model = bagging or random forest, not boosting. Lower variance of trees = bagging. Hard cases, lower bias = boosting.
  • Hybrid vs ensemble: ensemble = many models of the same kind, hybrid = different techniques combined. Multiple classifier systems and stacking; mixture of experts (a gating network weights specialist sub-networks); self-tuning (a genetic algorithm tunes a network; neuro-fuzzy); cooperating experts (one output feeds another).
  • Discriminative models (logistic, SVM, deep classifiers) learn P(y|x): accurate, need many labels. Generative models (Naive Bayes, GMM, VAE, GAN) learn P(x,y): cope with small, imbalanced or missing data and can create synthetic samples (GAN images to boost a rare class).

N. Deep learning jobs and reinforcement learning (Day 10, Q2b)

  • Three jobs: Identify (classify, detect with bounding boxes, segment), Create (generative AI; GAN = generator vs discriminator, deepfake risk), Act (learn what to do from feedback).
  • RL: agent → action → environment → (state, reward) → agent. No labelled answers, only a reward after actions. State, action, reward, policy. Explore vs exploit. Deep RL uses a deep network for the policy or for Q(s,a). Deep Q-learning estimates the expected reward of each action in each state. Continuous control (joint movements) often uses actor-critic (DDPG).
  • Q2b, reward factors (each tied to a criterion, with a sign): (1) task success and efficiency: large + for the right object in the right bin, small shaping + for approaching, a good grip and matching belt speed, small − each time step. (2) collision avoidance and safety: large − for contact with other objects, robots or humans; graded − inside a safe distance (from the cameras' tracked positions). (3) hardware protection: − for joint limits, awkward configurations, bad grip points, high torque or jerk.
  • Architecture: physical robot, target object, other objects, cameras, identification system (the classifier from part a), decision-making system (agent network: CNN encoder for the image state then dense layers to joint commands, plus a critic network). Loop: cameras observe, perception makes the state, agent chooses an action, safety layer checks it, arm moves, reward module scores. Label every arrow (state, action, reward).
  • Reduce real training danger (give at least two with reasons): simulate first (digital twin), with domain randomisation (lighting, textures, positions) for sim-to-real, then fine-tune slowly on the real arm. Safety layer with hard limits (joint angles, speed, force), protected zones, emergency stop. Penalise proximity, not only impact. Demonstrations or human feedback (imitation learning). Curriculum (one slow object, no obstacles first). Share experience across robots or use offline RL.
  • Warehouse robot example: + delivering a box, − per time step; large − for touching a person or shelf, graded − for coming closer than a safe distance; small − for jerk, high torque or low battery.

O. Signals: sampling, peaks, DTW, Fourier, wavelets (Days 11 and 12)

  • Signal: sampled at set time steps and quantised. Periodic f(t+T) = f(t). Even f(t) = f(−t). Odd f(t) = −f(−t). Sensors: temperature, proximity, infrared, LiDAR, pressure, water quality, accelerometer, gyroscope, microphone, camera, EEG.
  • Nyquist: fs ≥ 2·fmax; below it, high frequencies alias as low ones. Telephone 4 kHz needs 8 kHz. Bandwidth 10 kHz needs 20 kHz. Content to 120 Hz needs 240 Hz. Sampling at 50 Hz shows only up to 25 Hz. Samples = fs × duration (4 s at 50 Hz = 200; 2 s at 100 Hz = 200).
  • Peaks: slope 0 and changing + to −. Discrete signal: finite differences (forward f(x+Δ)−f(x), backward f(x)−f(x−Δ), central). [1,2,5,7,4,2] gives [1,3,2,−3,−2]; sign flips + to − at the value 7, the peak. Noise makes many wiggles, so use find_peaks filters: height (misses normal peaks if the level varies), distance (may drop a smaller real peak), prominence (usually best: how far a peak rises above the higher of its two bases), width (at half prominence; rejects sharp spikes). Prominence: extend a line left and right until a higher peak or the edge, take the lowest point each side (the bases), use the higher base, prominence = peak height − that base.
  • Baseline drift: estimate the baseline z and subtract, y corrected = y − z. ALS minimises S = Σ wi(yi − zi)² + λ Σ (Δ²zi)² (fit + roughness penalty). Asymmetric weights: points above the baseline (peaks) get a small weight p, points below get 1 − p. Suggested 0.001 ≤ p ≤ 0.1, 10² ≤ λ ≤ 10⁹, 5 to 10 iterations.
  • DTW (shifted or different-speed signals, different lengths; Euclidean needs equal length): D(i,j) = (yi − xj)²; A(i,j) = D(i,j) + min(A(i−1,j), A(i,j−1), A(i−1,j−1)); the path starts at (1,1), ends at (n,m), is monotonic and continuous; DTW distance = A(n,m). Cost grows as n × m. Example x = [0,2,3], y = [0,0,2,3] gives distance 0. Used in speech, signatures, temporal alignment.
  • Fourier: F(u) = Σ f(x)·e^(−i2πux/N), e^(ix) = cos x + i sin x. Gives which frequencies, not when. Example [2,3,4,4]: F(0) = 13 (the sum), F(1) = −2 + i, F(2) = −1, F(3) = −2 − i, |F(1)| = √5 ≈ 2.24. Not enough for signals whose frequency changes.
  • Wavelet (frequency and time, for non-stationary signals): a short localised wave. Low-pass (averaging) gives approximation, high-pass (differencing) gives detail, downsample by 2, repeat on the approximation. Haar: approx = (a+b)/√2, detail = (b−a)/√2. [9,7,3,5]: level 1 approx 8√2, 4√2, details −√2, √2; level 2 approx 12, detail −4. Coefficients [12, −4, −√2, √2], energy 164 = 144+16+2+2 (preserved, mostly in the first: compaction). [4,2,6,8] gives [10, 4, −√2, √2], energy 120.
  • Wavelet uses: features (mean, median, variance, std of each subband: 5 subbands × 4 statistics = 20 features), denoising (shrink small details), augmentation.
  • Signal pipeline: capture → process (denoise, filter, augment) → transmit (code, compress) → transform and features (Fourier, wavelet, adaptive or learned) → model.
  • Features from a vibration or ECG signal: time-domain statistics or histogram, frequency features (Fourier) or wavelet subband statistics.

P. Representation learning, autoencoders, anomaly detection (Day 13)

  • Basis: x in basis ui: wi = ⟨x, ui⟩ = xᵀui, reconstruct x̂ = Σ wi·ui. Example x = (1,2), u1 = (1,1)/√2, u2 = (−1,1)/√2: w1 = 3/√2, w2 = 1/√2, x̂ = (1,2). A good basis compacts the energy into a few coefficients (keep the big ones). Fourier, wavelets and PCA all choose a good basis. PCA learns it: the eigenvector with the largest eigenvalue of the covariance, subtract it, repeat.
  • Representation learning: learn a smooth, suitably sized representation that gets more abstract in deeper layers. Supervised: reuse with linear adaptation (freeze the pretrained net, train only a new linear layer) or fine-tuning (continue training the whole net). Self-supervised: the data supplies the target (reconstruct the input, match augmented views), then use the features for the downstream task with few labels. Generative (autoencoder) vs contrastive (pull two views of one item together, push different items apart). CLIP: image and text encoders trained so matching pairs have high cosine similarity (400M pairs).
  • Autoencoder: encoder squeezes to a narrow code, decoder rebuilds, loss ‖x − x̂‖². Under-complete (code smaller, compresses) vs over-complete (needs noise or sparsity or it just copies). Convolutional for images and signals. Denoising: corrupt the input, reconstruct the clean one. Uses: compression, features, denoising, interpolation, anomaly detection.
  • Anomaly types: point (a spike), contextual (30 °C in winter), collective (a flat signal for 1 s). Output a label or a score (needs a threshold).
  • Approaches: geometric (distance from the nearest cluster centre; no labels), statistical (low probability, or beyond mean ± 4σ; sliding window; no labels), classification (needs labelled normal and abnormal), autoencoder (reconstruction error; train on normal only).
  • Autoencoder workflow: train on normal data only → reconstruction errors on validation → threshold (mean + 3σ of the normal errors, or by acceptable false alarms) → flag new samples above it. Example errors .02, .03, .025, .04, .03: mean .029, σ ≈ .0066, threshold ≈ .049; a new error of .12 is an anomaly.
  • Judge a detector: accuracy is useless (always "normal" scores 99.9%). Use recall of anomalies, precision, F1, ROC or precision-recall curve; set the threshold from the cost of a miss against a false alarm. Detection says something is wrong; diagnosis says what (needs labelled causes, e.g. Bayes in Q2d).
  • Q2c answer (conveyor, 3,000 normal and 2 abnormal; 4 s at 50 Hz = 200 samples; 10-bin histogram + 20 wavelet statistics = 30 dimensions): do not agree with a two-class MLP.
  • Challenge 1, imbalance: 2 of 3,002 abnormal, so 99.93% by always saying "normal"; two samples cannot be split into train, validation and test; future failures may differ. Solution: anomaly detection trained on normal data (autoencoder on the 30-D features or raw signal, one-class, Gaussian, cluster distance); use the 2 abnormal only to test and set the threshold. If a classifier is wanted: augment (time-warp, jitter, scale), synthetic anomalies, report recall, precision, F1.
  • Challenge 2, features lose information: the histogram ignores time order (bin 1 shows about 63 abnormal vs 19 normal, matching a flat trace near 0 from about 2.0 to 2.7 s, but other bins overlap and two different waveforms can share a histogram). Frequency features are nearly identical except features 3 and 4 (about 1.45 and 2.1 abnormal vs 0.95 and 0.9 normal) and most of the 20 values are near zero; with 2 abnormal cases we cannot tell which differences are reliable. Solution: 1D conv or LSTM autoencoder on the raw sequence, wavelet coefficients over time, a run-length feature, DTW for phase differences, choose features with domain knowledge.
  • Challenge 3 (optional): normalising each sequence to 0 to 1 hides absolute amplitude (a loose part vibrating harder). Keep the level as a separate feature.
  • "Do you agree?" Give a clear yes or no, reasons tied to numbers (3,000 vs 2) and the figure, each challenge with a matching solution, and the evaluation (recall, precision, F1, threshold from cost).

Q. Multimodal sensing and sensor fusion (Day 14)

  • Modality: a way something is expressed or perceived (audio, image, inertial, text, temperature). Raw modalities can become abstract ones (detected objects, sentiment). Inertial: gesture and activity recognition. Audio: sound classification, speaker recognition, machine anomaly detection (SMD assembly machine sound at 192 kHz). Vision: objects, defects, flood monitoring (210 water-level sensors and 49 CCTV cameras).
  • Augmentation for sensor windows: scaling (multiply by a random factor), magnitude filtering (smooth random curve near 1), jittering (add noise), time-warping (stretch the time axis). Makes models robust to multiplicative noise, additive noise and timing changes.
  • Why fuse: higher-level representation, better accuracy (smaller spread), completeness. Kinds: across sensors, across domains, across attributes (temperature, pressure and humidity give air refractive index), across time.

S. My traps (mistakes made in the rounds)
  • Proportion = count ÷ TOTAL in the node. "1 and 5" is 1/6, 5/6.
  • Child weight = child size ÷ node size, and the weights add to 1.
  • High gain = children are pure, not sizes split 50/50. Pure child contributes 0.
  • Backprop δ uses (T − O). Target above output gives a positive δ.
  • K-means centre is the mean. Every point in one cluster only.
  • Silhouette b = average distance to the other cluster's points, not their positions.
  • Elbow is where gains flatten, not the lowest WCSS.
  • Recall ≠ accuracy. Recall = TP/(TP+FN).
  • KMO under 0.5 or Bartlett p over 0.05 = PCA unsuitable. Do not remove correlation.
  • Kaiser is eigenvalue strictly over 1. LDA axes = min(p, c−1).
  • More support vectors means smaller C. Large C: fewer SVs, narrow margin.
  • SVM class = sign of the score. A score of 0.5 is still class +1, inside the margin.
  • Imbalance fixes are class weights, SMOTE, over or undersampling. One-vs-rest is for many classes.
  • Scaler and PCA are fitted after the split, on training data only.
  • Dropout is off at test time. Never zero-initialise. Higher learning rate is not always faster.
  • A leaked target (in PCA or features) inflates accuracy. Exclude it.
  • Nyquist is a sampling rate of at least 2 × fmax. A 50 Hz sampler shows up to 25 Hz.
  • LSTM params are 4× a SimpleRNN (not 2×). Flatten has 0 parameters; the first Dense after it dominates.
  • Split time series by time order or session, never randomly.
  • Haar detail = (second − first)/√2, approximation = (sum)/√2. Check energy is preserved.
  • Noisy labels: bagging or random forest, not boosting. Degradation (deep net worse on train) is not overfitting.
  • Autoencoder anomaly detector: train on normal only; threshold = mean + 3σ of normal errors; judge by recall, precision, F1, not accuracy.
  • Dropout and batch-norm statistics: dropout off at test; BN has 4 params per channel (2 trainable).
